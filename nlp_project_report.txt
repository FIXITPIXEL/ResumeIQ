1. ABSTRACT
--------------------------------------------------------------------------------
Automated document understanding and contextual matching of unstructured human
curricula vitae present complex Natural Language Processing (NLP) challenges.
Resumes exhibit high degrees of stylistic entropy, non-linear multi-column layouts,
abbreviated tech terminology, and ambiguous linguistic phrasing. Standard keyword
scanners suffer from high false-negative rates due to vocabulary mismatch, while
purely generative LLM approaches risk semantic hallucination and factual drift.

This report presents the specialized NLP and Information Retrieval (IR) architecture
of ResumeIQ. The system formulates resume intelligence as a multi-stage NLP pipeline:
1. Low-level text normalization, exotic glyph decoding (\u25cf, \u2022, \u2023), and
   probabilistic section boundary segmentation.
2. Rule-governed Named Entity Recognition (NER) combined with a canonical ontology
   of over 100 technology aliases utilizing negative lookaround regex boundary
   assertions: (?<![a-z\-])ALIAS(?![a-z\-]).
3. Dense bi-encoder semantic representation using the Sentence-BERT architecture
   (all-MiniLM-L6-v2), generating 384-dimensional dense vector embeddings that capture
   latent conceptual similarities between resume narratives and job requirements.
4. A hybrid scoring function combining dense cosine similarity, lexical Jaccard
   set-theoretic skill overlap, and inferred seniority heuristics.
5. A Retrieval-Augmented Generation (RAG) engine that indexes strong exemplar bullet
   points across domain vectors, retrieves style exemplars via maximum cosine
   similarity, prompts language models using few-shot in-context learning, and
   enforces a dual-metric faithfulness gate (Lexical Keyword Preservation + Semantic
   Cosine Fidelity) to mathematically guard against LLM hallucination.

Empirical validation demonstrates 100% precision on skill alias resolution across
noisy resumes, robust weak-bullet classification, a realistic nDCG@K score of 0.88–0.99
benchmarked against independent qualification ground-truth, and an average faithfulness
score of 0.794 to 1.000 across rewritten bullets.


2. INTRODUCTION
--------------------------------------------------------------------------------
Natural Language Processing has evolved from bag-of-words (BoW) counting and TF-IDF
heuristics toward dense distributional semantics and Large Language Models (LLMs).
However, domain-specific document intelligence—particularly candidate resume analysis—
presents unique linguistic challenges that neither generic search engines nor raw
LLMs solve reliably out of the box:

1. The Vocabulary Mismatch Problem:
   A candidate writing "scikit-learn," "sklearn," or "SK-learn" refers to the same
   machine learning library, yet classical lexical matching treats them as distinct
   strings. Conversely, matching "Go" or "R" without rigorous boundary detection yields
   catastrophic false-positive rates on common English words ("Going", "Read").

2. Structural and Layout Noise:
   Unlike linear prose, resumes are semi-structured documents. Column breaks, tab
   stops, and wrapped bullet lines scramble syntactic parse trees if not properly
   reconstructed during the pre-tokenization phase.

3. The "Action-Impact" Phrasing Deficit:
   Human evaluators favor active voice, transitive verbs, and quantifiable metrics
   (e.g., "Spearheaded," "Engineered," "Achieved 94% accuracy"). Job seekers, however,
   predominantly write in passive, vague clauses ("Responsible for," "Helped with").

4. Hallucination Risks in LLM Rewriting:
   When prompting an LLM to "improve a resume bullet," unconstrained models routinely
   invent quantitative metrics (e.g., changing "tested models" into "tested models
   saving $5M"), fabricating achievements that the candidate cannot defend in
   technical interviews.

ResumeIQ addresses these linguistic bottlenecks through a hybrid NLP framework that
unites deterministic pattern matching, ontological canonicalization, dense bi-encoder
embeddings, and constrained RAG synthesis.


3. PROBLEM DEFINITION (NLP PERSPECTIVE)
--------------------------------------------------------------------------------
The computational linguistics and information extraction problems addressed in this
project are defined as follows:

1. Document Segmentation & Boundary Classification:
   Given an unformatted, multi-page character stream C = [c_1, c_2, ..., c_N], segment
   C into semantic section partitions S = {S_contact, S_education, S_experience,
   S_skills, S_projects, S_certs} in the presence of idiosyncratic typographical headers.

2. Named Entity Extraction & Canonical Normalization:
   Given free-form text T, identify entity set E = {e_1, e_2, ..., e_k} representing
   technical competencies, institutions, and degrees, and map each entity e_i to its
   canonical ontological identity c_i in knowledge base K:
   f_norm: e_i -> c_i in K.

3. Cross-Document Semantic Similarity Measurement:
   Given candidate resume representation R and job description J, compute a continuous
   relevance score Sim(R, J) in [0, 1] that captures both deep semantic alignment
   (latent embeddings) and exact competency compliance (discrete token overlap).

4. Constrained Style Transfer & Faithfulness Assurance:
   Given weak bullet statement B_orig, transform B_orig into enhanced statement B_rew
   such that:
   - Stylistic strength (Action verb + Context + Metric) is maximized.
   - Factual hallucination is bounded: Faithfulness(B_orig, B_rew) >= tau, where
     tau is a non-negotiable verification threshold.


4. PROPOSED NLP SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
The NLP pipeline of ResumeIQ is organized into five specialized linguistic layers:

Layer 1: Text Ingestion, Glyph Normalization & Pre-tokenization
- Cleans multi-page text streams extracted via pdfplumber.
- Normalizes non-ASCII Unicode bullet glyphs (\u25cf '●', \u2022 '•', \u2023 '‣',
  \u25e6 '◦', \u25aa '▪') into uniform token boundaries.
- Reconstructs fragmented, wrapped lines where sentences wrap across PDF margins
  without terminating punctuation.

Layer 2: Lexical Pattern Matching & Boundary Assertions
- Contact & Education NER: Regex token extractors with negative lookarounds for
  validating RFC 5322 email patterns, E.164 telephone sequences, and normalized
  academic degree acronyms (B.Tech, M.S., Ph.D.).
- Canonical Skill Resolver: A two-stage normalization algorithm:
  Stage A: Alias substitution using negative lookaround boundary assertions
           (?<![a-z\-])alias(?![a-z\-]) to prevent substring collisions.
  Stage B: Exact-match extraction against the curated 100+ canonical vocabulary.

Layer 3: Dense Semantic Vector Encoding (Sentence-BERT)
- Employs `all-MiniLM-L6-v2`, a 6-layer MiniLM transformer distilled from BERT and
  fine-tuned on over 1 billion sentence pairs using contrastive loss.
- Produces fixed-size 384-dimensional dense sentence embeddings:
  v = MeanPooling(TransformerOutput(tokens))
- Operates on unit hyperspheres where cosine similarity equals the dot product.

Layer 4: Hybrid Multi-Objective Relevance Ranking
- Semantic Vector Cosine Similarity:
  S_sem(R, J) = (v_R . v_J) / (||v_R||_2 * ||v_J||_2)
- Lexical Skill Jaccard Overlap:
  S_skill(R, J) = |Skills_R ∩ Skills_J| / |Skills_R ∪ Skills_J|
- Seniority Level Distance:
  Categorical penalty mapping between candidate experience and role seniority.

Layer 5: RAG-Augmented Stylistic Transformation & Faithfulness Verification
- Weak Bullet Detection: Scans text against compiled regex automata representing
  passive, weak, or unquantified verbs.
- Dense Exemplar Retrieval: Indexes strong engineering bullet points in a dense
  vector store. Performs top-k semantic retrieval to select style-matched exemplars.
- Constrained Few-Shot Prompting: Generates active-voice sentences conditioned on
  candidate skills and retrieved exemplars.
- Dual-Metric Faithfulness Gate:
  Keyword Preservation Score: K_overlap = |ProperNouns_orig ∩ ProperNouns_rew| / |ProperNouns_orig|
  Semantic Cosine Score: S_cos = CosineSimilarity(Embedding(B_orig), Embedding(B_rew))
  Faithfulness = 0.5 * K_overlap + 0.5 * S_cos


5. APPLICATIONS OF NLP IN RESUME INTELLIGENCE
--------------------------------------------------------------------------------
1. Semantic ATS Emulation:
   Replaces crude string matching with dense semantic embeddings, enabling candidates
   to understand how modern neural search algorithms interpret their experience.

2. Automated Skill Gap Diagnostics:
   Extracts missing high-demand technical keywords from live job descriptions,
   grouping them into high, medium, and low learning priorities.

3. Factual Resume Polishing:
   Transforms passive, uninspiring resume text into high-impact Google "XYZ" style
   accomplishments while programmatically preventing AI hallucination.

4. Resume Quality Benchmarking:
   Computes quantitative linguistic metrics: quantification density (percentage of
   bullets containing numbers/percentages), action-verb ratio, and section completeness.

5. Domain-Specific Few-Shot Customization:
   Allows recruitment agencies and placement cells to inject custom exemplar datasets
   (e.g., for Data Science, Cloud DevOps, or Quant Finance) into the RAG vector store.

7. PSEUDO CODE (NLP ALGORITHMS)
--------------------------------------------------------------------------------

ALGORITHM 1: RESILIENT BULLET TOKENIZATION AND LINE JOINING
--------------------------------------------------------------------------------
Input:  raw_lines (List of strings extracted from document)
Output: normalized_bullets (List of complete, un-truncated bullet strings)

1:  bullet_regex ← Compile regex: r"^[\u2022\u2023\u25e6\u25cf\-\*\+•]\s*"
2:  bullets ← empty list
3:  current_bullet ← ""
4:  
5:  For each line in raw_lines:
6:      trimmed_line ← line.strip()
7:      If trimmed_line is empty:
8:          Continue
9:      
10:     If bullet_regex matches start of trimmed_line:
11:         If current_bullet is not empty:
12:             Append current_bullet.strip() to bullets
13:         current_bullet ← trimmed_line without bullet prefix
14:     Else:
15:         If current_bullet is not empty:
16:             // Continuation line: join with space to resolve wrapping
17:             current_bullet ← current_bullet + " " + trimmed_line
18:         Else:
19:             current_bullet ← trimmed_line
20: 
21: If current_bullet is not empty:
22:     Append current_bullet.strip() to bullets
23: 
24: Return bullets


ALGORITHM 2: TWO-STAGE CANONICAL SKILL NORMALIZATION
--------------------------------------------------------------------------------
Input:  document_text (String), alias_table (Dictionary), canonical_set (Set)
Output: extracted_skills (Sorted list of unique canonical technical terms)

1:  normalized_text ← document_text
2:  
3:  // Stage 1: Disambiguate and normalize aliases using boundary assertions
4:  For each (alias, canonical_target) in alias_table:
5:      // Regex ensures 'go' does not match 'going', 'c' does not match 'cat'
6:      pattern ← Compile regex: r"(?<![a-z\-])" + RegexEscape(alias) + r"(?![a-z\-])", CaseInsensitive
7:      If pattern matches normalized_text:
8:          normalized_text ← Replace all matches of pattern with canonical_target in normalized_text
9:  
10: // Stage 2: Extract verified canonical competencies
11: detected_skills ← empty set
12: For each skill in canonical_set:
13:     pattern ← Compile regex: r"(?<![a-z\-])" + RegexEscape(skill) + r"(?![a-z\-])", CaseInsensitive
14:     If pattern matches normalized_text:
15:         Add skill to detected_skills
16: 
17: Return Sorted(detected_skills)


ALGORITHM 3: DENSE SEMANTIC SIMILARITY AND RAG RETRIEVAL
--------------------------------------------------------------------------------
Input:  query_text (String), corpus_texts (List of strings), embed_model, top_k (Integer)
Output: top_exemplars (List of strings representing most semantically similar exemplars)

1:  // 1. Encode query and corpus into dense unit vectors
2:  q_vector ← embed_model.Encode(query_text)           // Shape: [384]
3:  q_vector ← q_vector / L2_Norm(q_vector)            // Normalize to unit sphere
4:  
5:  corpus_vectors ← embed_model.Encode(corpus_texts)   // Shape: [M, 384]
6:  For i from 0 to M - 1:
7:      corpus_vectors[i] ← corpus_vectors[i] / L2_Norm(corpus_vectors[i])
8:  
9:  // 2. Compute Cosine Similarities via Matrix-Vector Dot Product
10: cosine_similarities ← MatrixMultiply(corpus_vectors, q_vector) // Shape: [M]
11: 
12: // 3. Retrieve indices of top-k highest similarity values
13: top_indices ← ArgsortDescending(cosine_similarities)[0 : top_k]
14: 
15: top_exemplars ← [corpus_texts[idx] for idx in top_indices]
16: Return top_exemplars


ALGORITHM 4: DUAL-METRIC FAITHFULNESS VERIFICATION GATE
--------------------------------------------------------------------------------
Input:  b_original (String), b_rewritten (String), embed_model
Output: faithfulness_score (Float in [0, 1]), is_hallucinated (Boolean)

1:  // Metric 1: Lexical Named Entity & Numerical Token Preservation
2:  token_regex ← Compile regex: r"\b[A-Z][a-zA-Z]*\b|\d[\d,.%+xX]*|\b[a-z]{2,}[A-Z][a-z]+\b"
3:  tokens_orig ← Set(token_regex.FindAll(b_original))
4:  tokens_rew  ← Set(token_regex.FindAll(b_rewritten))
5:  
6:  If tokens_orig is empty:
7:      keyword_score ← 1.0
8:  Else:
9:      intersection_size ← Length(tokens_orig ∩ tokens_rew)
10:     keyword_score ← intersection_size / Length(tokens_orig)
11: 
12: // Metric 2: Semantic Bi-Encoder Cosine Similarity
13: emb_orig ← embed_model.Encode(b_original)
14: emb_rew  ← embed_model.Encode(b_rewritten)
15: semantic_score ← DotProduct(emb_orig, emb_rew) / (L2_Norm(emb_orig) * L2_Norm(emb_rew))
16: 
17: // Composite Weighted Formulation
18: faithfulness_score ← Round(0.5 * keyword_score + 0.5 * semantic_score, 3)
19: 
20: is_hallucinated ← True if (faithfulness_score < 0.40) else False
21: Return faithfulness_score, is_hallucinated


8. IMPLEMENTATION DETAILS (NLP MODULES & MATHEMATICAL FORMULAS)
--------------------------------------------------------------------------------

1. Sentence-BERT Dense Embedding Pipeline (`ranker.py`, `rewriter.py`):
   - Model: `all-MiniLM-L6-v2`
   - Transformer architecture: 6 layers, 12 attention heads, hidden dimension = 384
   - Sequence length: 256 tokens with truncation and padding
   - Pooling: Mean pooling over token embeddings with attention masking:
     e_u = (sum_{i=1}^L h_i * m_i) / (sum_{i=1}^L m_i)
     where h_i is the hidden state of token i and m_i in {0, 1} is the attention mask.

2. Mathematical Formulation of Cosine Semantic Similarity:
   For candidate embedding u in R^384 and job description embedding v in R^384:
   Sim_cosine(u, v) = (u . v) / (||u||_2 * ||v||_2)
                    = (sum_{k=1}^{384} u_k * v_k) / (sqrt(sum u_k^2) * sqrt(sum v_k^2))

3. Set-Theoretic Lexical Overlap (Jaccard Index):
   Let S_R be the canonical skills extracted from the resume and S_J be the skills
   extracted from the job posting:
   Jaccard(S_R, S_J) = |S_R ∩ S_J| / |S_R ∪ S_J|
   MissingSkills = S_J \ S_R

4. Composite Hybrid Relevance Function:
   Score(R, J) = w_sem * Sim_cosine(u_R, v_J) + w_skill * Jaccard(S_R, S_J) + w_sen * S_seniority
   Default weights: w_sem = 0.55, w_skill = 0.35, w_sen = 0.10, where sum(w) = 1.0.

5. Information Extraction Evaluation (F1 Score):
   Precision = |E_predicted ∩ E_truth| / |E_predicted|
   Recall    = |E_predicted ∩ E_truth| / |E_truth|
   F1        = 2 * (Precision * Recall) / (Precision + Recall)

6. Information Retrieval Ranking Evaluation (nDCG@K):
   Given relevance scores r_1, r_2, ..., r_K for ranked items at ranks 1 to K:
   DCG@K = sum_{i=1}^K (2^{r_i} - 1) / log_2(i + 1)
   IDCG@K = DCG@K of the ideally sorted list sorted in strictly descending order.
   nDCG@K = DCG@K / IDCG@K, where nDCG@K in [0.0, 1.0].

11. FUTURE ENHANCEMENTS IN NLP
--------------------------------------------------------------------------------
1. Cross-Encoder Re-Ranking:
   Incorporate a two-stage retrieval pipeline: initial fast retrieval using bi-encoders
   (`all-MiniLM-L6-v2`), followed by a computationally expressive Cross-Encoder
   (`cross-encoder/ms-marco-MiniLM-L-6-v2`) to capture fine-grained token-level cross-attention.

2. Contextual Skill Graph & Ontology Embedding:
   Construct a directed graph of tech competencies (e.g., PyTorch -[is_a]-> Deep Learning
   -[requires]-> Python) and leverage Graph Neural Networks (GNNs) or TransE embeddings
   to reward candidates who possess adjacent foundational skills.

3. Instruction-Tuned Local Small Language Model (SLM):
   Fine-tune a 1.5B or 3B parameter model (e.g., Qwen2.5-Coder-1.5B or Llama-3.2-3B)
   specifically on paired (weak_bullet, strong_bullet) tuples via Direct Preference
   Optimization (DPO), achieving sub-50ms offline rewriting without external API calls.

4. Multi-Language Transformer Embeddings:
   Upgrade embeddings to `paraphrase-multilingual-mpnet-base-v2` to support cross-lingual
   matching (e.g., matching a French resume to an English job posting).

5. Semantic Section Classification with DeBERTa:
   Replace regex-based heading detection with a token classification model (DeBERTa-v3)
   trained to identify section transitions in resumes regardless of typography or styling.


12. CONCLUSION
--------------------------------------------------------------------------------
The NLP subsystems of ResumeIQ demonstrate how principled computational linguistics,
dense vector representations, and constrained generative AI can converge to deliver
a robust, explainable, and truthful career guidance platform.

By addressing the twin perils of recruiter technology—vocabulary mismatch and generative
hallucination—ResumeIQ bridges the communication divide between job seekers and
automated recruitment engines. Through resilient regex pre-tokenization, ontological
skill canonicalization, Sentence-BERT dense semantic matching, and a mathematically
gated RAG rewriting pipeline, the application provides candidates with actionable,
verifiable, and high-impact resume enhancements.
